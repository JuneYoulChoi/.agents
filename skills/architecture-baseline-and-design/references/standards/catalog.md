# International-standard profile catalog

Use this catalog to choose the smallest relevant profile. Standards describe
architecture information, requirements, quality models, lifecycle processes,
or information items; they do not prescribe one software architecture pattern.

| Canonical ID | Use when | Profile |
| --- | --- | --- |
| `iso_iec_ieee_42010_2022` | an architecture description, viewpoint, view, model, concern, or correspondence is material | [ISO/IEC/IEEE 42010](iso-42010.md) |
| `iso_iec_ieee_29148_2018` | stakeholder/system/software requirements or external interfaces need a controlled specification | [ISO/IEC/IEEE 29148](iso-29148.md) |
| `iso_iec_25010_2023` | a product-quality model or measurable product QAS is needed | [ISO/IEC 25010 and 25019](iso-25010-25019.md) |
| `iso_iec_25019_2023` | quality-in-use outcomes or stakeholder outcomes are material | [ISO/IEC 25010 and 25019](iso-25010-25019.md) |
| `iso_iec_ieee_12207_2026` | software lifecycle processes, responsibilities, or evidence are contractually relevant | [ISO/IEC/IEEE 12207 and 15288](iso-12207-15288.md) |
| `iso_iec_ieee_15288_2023` | system lifecycle processes and system/software boundaries are relevant | [ISO/IEC/IEEE 12207 and 15288](iso-12207-15288.md) |
| `iso_iec_ieee_15289_2019` | lifecycle information-item content and ownership need control | [ISO/IEC/IEEE 15289](iso-15289.md) |

For each selected profile record canonical ID, edition, intent (`guidance`,
`alignment`, or `conformance`), scope/entity, rationale, owner, source evidence,
deviations, review trigger, and affected artifacts. Public ISO pages establish
identity and scope only. Formal conformance requires authorized normative text
and clause-level evidence; this catalog is not a substitute.

Do not activate every profile by default. If no profile is selected, retain a
`standards_applicability` result with rationale so later evidence can reopen G2.
